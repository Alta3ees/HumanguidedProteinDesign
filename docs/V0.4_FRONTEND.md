# v0.4 Interactive Research Workspace

v0.4 turns HGD's persistent scientific archive into a local interactive workspace.

The canonical source of truth remains:

```text
data/projects/<project>/design_archive.json
```

The React frontend never edits archive JSON directly. All scientific actions go through the local FastAPI API and validated Python domain/action layer.

## Architecture

```text
design_archive.json + project-local scientific files
                    |
                    v
        HGD Python archive/actions
                    |
          PyRosetta / PyMOL
                    |
                    v
       local FastAPI (127.0.0.1)
                    |
                    v
       React + TypeScript workspace
```

HGD does not require a hosted service, account, or cloud database for normal operation.

## Current workspace features

### Project and lineage

- create and switch local projects;
- register starting/imported/generated designs;
- radial parent/child design map;
- sequence-derived child creation without rewriting history;
- accepted, rejected, deferred, active, and deprioritized provenance.

### Structures

- attach PDB, CIF/mmCIF, ENT, and PQR structures;
- associate multiple structural hypotheses with one design;
- retain source/method/confidence metadata;
- launch selected structures in local PyMOL;
- delete copied project-local structures while preserving historical evidence.

### PyRosetta design tools

- baseline score of the current structure;
- one hypothesis-driven point mutation;
- matched local repacking/minimization and ΔScore comparison;
- selected Rosetta score-term breakdown;
- structural-neighborhood context;
- saturation scan of all 19 non-WT amino acids at one position;
- Accept / Defer / Reject decision directly after mutation evaluation;
- automatic child-node creation for every evaluated mutation.

HGD checks that the selected structure sequence is compatible with the design before mutation/scanning operations.

### Evidence and scientific files

Evidence categories are:

```text
computational
experimental
literature
note
```

Files are copied into the local project and referenced using project-relative paths where possible.

Native previews currently recognize common scientific formats including:

- FASTA;
- CSV/TSV/XLSX;
- JSON;
- Rosetta `.sc` scorefiles;
- PDF;
- PNG/JPG/SVG/TIFF images;
- Markdown/text/log files;
- molecular structure files.

Unknown/raw instrument formats can still be archived as evidence even when HGD cannot preview them.

## Project context export

The workspace exposes one project-level Markdown export:

**Export context for LLM (.md)**

It generates:

```text
PROJECT_CONTEXT.md
```

The file contains a readable project overview and detailed scientific records followed by the complete archive JSON in a fenced appendix. It is intended as a portable snapshot for an LLM, collaborator, or downstream text-based workflow.

`PROJECT_CONTEXT.md` is generated from the archive; it is not a second source of truth.

## Run locally

From the repository root:

```bash
conda activate human-guided-protein-design
hgd
```

For frontend development, use a second terminal:

```bash
cd frontend
npm install
npm run dev
```

Open the local Vite URL, normally `http://localhost:5173`.

## Projects root

Default:

```text
data/projects/
```

Override locally with:

```bash
HGD_PROJECTS_ROOT=/path/to/projects hgd
```

## Validation

Python:

```bash
python -m pytest -q
```

Frontend:

```bash
cd frontend
npm install
npm run build
```

## v0.4 boundary

The web workspace is now the primary HGD user interface. CLI scripts remain useful for validation and direct workflows, but new scientist-facing capabilities should normally be added to the central Python action layer first and then surfaced through the API/UI.
